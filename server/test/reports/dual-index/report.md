# 双索引短文实测报告

本次实测使用 DeepSeek `deepseek-flash` 做知识提取，使用 SiliconFlow `BAAI/bge-m3` 做向量化。所有网络调用使用已有本地配置；结果为真实返回值，未使用模拟向量。未写入数据库。

## 1. 测试文章

原文文件：[dual-index-article.mdx](dual-index-article.mdx)。

```md
---
title: 星河笔记检索说明
---

## 内容处理

星河笔记将文档按标题切分为章节。章节原文用于生成 Chunk，语义知识用于构建 Wiki 节点。

## 双索引

Chunk 索引用于定位原文，Wiki 索引用于定位概念和实体。两类索引使用同一个向量模型，检索结果通过章节关联回查原文。
```

## 双路检索、重排与答案生成验证

通过 Hono 的实际 `POST /api/search` 路由调用本地 pgvector 和真实模型，未启动额外监听端口。问题：哪种索引用于定位概念和实体？两种索引各有什么作用？

| 步骤         | 实际结果                                                            |
| ------------ | ------------------------------------------------------------------- |
| 问题向量化   | BAAI/bge-m3，1024 维；输入 Token 20                                 |
| 双路召回     | 每路上限 30；短文库实际 Chunk 2 条、Wiki 10 条                      |
| 合并去重     | 12 条候选，重复 0 条                                                |
| Rerank       | BAAI/bge-reranker-v2-m3，12 → 5；输入 Token 1362                    |
| 答案生成     | deepseek-flash，只使用 Top 5；输入 762 / 输出 317 / 合计 1079 Token |
| 完整请求耗时 | 2804 ms（本次样本，不是性能基准）                                   |

| 来源 | 标题             | 类型  | 重排分数 |
| ---- | ---------------- | ----- | -------- |
| S1   | 星河笔记检索说明 | chunk | 0.998344 |
| S2   | 双索引           | wiki  | 0.996825 |
| S3   | Wiki 索引        | wiki  | 0.996808 |
| S4   | Chunk 索引       | wiki  | 0.995016 |
| S5   | 向量模型         | wiki  | 0.148638 |

实际答案：

用于定位概念和实体的是 **Wiki 索引** [S1][S3]。

两种索引的作用：

- **Chunk 索引**：用于定位原文 [S1][S3][S4]。
- **Wiki 索引**：用于定位概念和实体 [S1][S2][S3]。

二者构成“双索引”，用途不同，分别定位原文、概念和实体 [S2][S4]；两类索引使用同一个向量模型，检索结果可通过章节关联回查原文 [S1][S5]。

完整响应（含入选文本、来源、分数与用量）保存在 [10-answer.json](10-answer.json)。样本库不足 30 条，独立数据库测试另构造每路 35 条，确认分别只返回 Top 30；内存测试验证 30 + 30 → 去重 59 → 重排 5 → LLM 仅见 5 条。当前实现未启用 Graph Expand，也未接入前端问答页面。
